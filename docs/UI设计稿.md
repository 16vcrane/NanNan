# 喃喃（Nannan）微信小程序 UI 设计稿

> 版本：MVP UI v1.0\
> 设计依据：当前 UI 设计总览图（8 个核心页面）\
> 产品定位：记录生活的每一份确幸，让用户通过轻量日记、情绪记录与 AI
> 回响，持续看见自己的生活。\
> 平台：微信小程序\
> 视觉关键词：温暖、治愈、克制、生活感、轻 AI、旧纸张质感

------------------------------------------------------------------------

## 1. UI 设计目标

### 1.1 核心体验

喃喃不是传统的效率型日记工具，而是一个以「记录 → 回望 →
理解自己」为核心的生活记录产品。

UI 需要重点传达：

-   **低压力记录**：用户打开首页即可快速完成情绪打分和一句话记录。
-   **温暖陪伴感**：AI
    不应该表现得像冷冰冰的工具，而更像一个温柔的生活观察者。
-   **时间沉淀感**：通过「时光」将零散记录组织成可回看的生活轨迹。
-   **情绪可视化**：让用户看到自己的情绪变化，而不仅仅是文字列表。
-   **生活感而非科技感**：AI 是产品能力，不应该成为视觉主体。
-   **内容优先**：图片、文字、情绪和标签共同构成一条生活记录。

### 1.2 设计原则

1.  **少操作**：核心行为尽量控制在 1～3 步内。
2.  **弱边界**：大量使用圆角卡片、柔和阴影和留白，降低工具感。
3.  **暖色优先**：米白、奶油、棕色作为基础色，情绪颜色作为辅助色。
4.  **层级清晰**：页面标题 \> 核心状态 \> 内容 \> 辅助信息。
5.  **统一组件**：情绪、标签、卡片、底部 Tab、按钮等组件全局复用。
6.  **微信小程序原生感**：保留微信小程序导航栏、右上角胶囊区域和底部安全区适配。

# 2. 全局 Design System

## 2.1 色彩规范

### 基础色

  Token                     HEX         用途
  ------------------------- ----------- ------------------------
  `color-bg-primary`        `#FBF7F0`   页面主背景，旧纸张质感
  `color-bg-card`           `#FFFDFC`   卡片背景
  `color-bg-soft`           `#F6EFE5`   次级背景、选中区域
  `color-brown-primary`     `#6B4933`   主按钮、重点操作
  `color-brown-dark`        `#493326`   主标题、深色文字
  `color-brown-secondary`   `#8C6A50`   次级文字、辅助内容
  `color-border`            `#E9DED0`   卡片边框、分割线
  `color-text-primary`      `#33271F`   一级文字
  `color-text-secondary`    `#7C7067`   二级文字
  `color-text-tertiary`     `#A79C93`   占位、说明文字
  `color-white`             `#FFFFFF`   按钮、内容区域

### 情绪色

情绪颜色不仅用于文字，也用于情绪趋势图、状态标签、情绪仪表盘。

  情绪   HEX         使用场景
  ------ ----------- ----------------------
  平静   `#73A9D9`   首页/AI 回响默认状态
  愉悦   `#7BB879`   积极情绪
  高亢   `#F08A45`   高能量状态
  低落   `#8B7BCB`   低能量状态
  中性   `#B7B0A8`   未明确情绪

> 视觉上建议使用低饱和度情绪色，避免出现强烈的娱乐 App 或游戏化效果。

------------------------------------------------------------------------

## 2.2 字体规范

微信小程序优先使用系统字体。

### 字体层级

  Token                  建议字号   字重 使用场景
  -------------------- ---------- ------ --------------------------------------
  `font-display`             24px    600 页面核心问题，如「今天过得怎么样？」
  `font-title`               20px    600 页面标题
  `font-section`             16px    600 卡片标题、模块标题
  `font-body`                14px    400 正文
  `font-body-medium`         14px    500 标签、按钮
  `font-caption`             12px    400 日期、辅助说明
  `font-small`               11px    400 次要信息

### 文字风格

-   标题使用深棕色，不使用纯黑。
-   正文使用偏灰棕色。
-   AI 生成内容可以适当增加行高，营造阅读感。
-   避免大面积粗体。
-   正文建议 `line-height: 1.7` 左右。

------------------------------------------------------------------------

## 2.3 圆角规范

  Token             Radius 使用场景
  --------------- -------- ------------------
  `radius-sm`          8px 小标签、按钮
  `radius-md`         12px 输入框、小卡片
  `radius-lg`         16px 主卡片
  `radius-xl`         20px 大型内容卡片
  `radius-pill`      999px 情绪标签、筛选器

------------------------------------------------------------------------

## 2.4 阴影规范

整体 UI 不使用明显的 Material Design 强阴影。

推荐：

``` text
box-shadow:
0 4px 16px rgba(86, 61, 40, 0.06);
```

重点卡片可以使用：

``` text
box-shadow:
0 6px 24px rgba(86, 61, 40, 0.08);
```

原则：

-   阴影颜色偏暖。
-   阴影透明度低。
-   卡片主要依靠背景色差和留白形成层次。

------------------------------------------------------------------------

## 2.5 间距规范

建议基于 4px / 8px 间距体系。

  Token           值 用途
  ----------- ------ ----------------
  `space-1`      4px 图标与文字
  `space-2`      8px 小元素
  `space-3`     12px 标签、紧凑内容
  `space-4`     16px 常规模块间距
  `space-5`     20px 卡片内边距
  `space-6`     24px 页面模块间距
  `space-8`     32px 大区块间距

# 4. 全局底部 TabBar

产品主要包含四个一级入口：

  Tab    图标语义             页面
  ------ -------------------- ----------
  首页   房屋 / Home          今日心情
  日记   日历 / Diary         时光瀑布
  发现   圆形趋势 / Explore   发现
  我的   用户 / Profile       设置

### TabBar 设计

-   高度：约 64～72px + 底部安全区。
-   背景：半透明/暖白。
-   顶部保持极弱分割线或阴影。
-   当前 Tab 使用深棕色。
-   非当前 Tab 使用灰棕色。
-   图标尺寸建议 20～22px。
-   文字尺寸建议 10～11px。

### Tab 状态

``` text
Active
图标：深棕
文字：深棕
可增加极浅暖色背景

Inactive
图标：#9D938A
文字：#9D938A
```

# 5. 页面设计

# 5.1 首页 ------ 今日心情

页面定位：

> 今日记录入口，完成「情绪打分 + 快速记录 + 图片添加」。

### 页面结构

``` text
今日心情
记录生活的每一份确幸

┌─────────────────────────┐
│ 📅 8月15日 · 周四        │
│                         │
│ 今天过得怎么样？         │
│ 给自己的今天，打个分吧~  │
│                         │
│      情绪仪表盘          │
│  低落 ←  平静  → 高亢   │
└─────────────────────────┘

┌─────────────────────────┐
│ 试着写下今天最想记住的一刻 │
│ 哪怕只有一句话。           │
│                           │
│ ✎ 写下你的心情...         │
└─────────────────────────┘

添加图片（最多3张）

[ + ] [图片1] [图片2]

        [ 保存日记 ]
```

### 核心组件

#### 1. 日期信息

-   图标：日历
-   日期格式：`8月15日 · 周四`
-   颜色：次级棕色
-   字号：12～13px

#### 2. 情绪仪表盘

视觉特点：

-   半圆弧形仪表盘。
-   颜色从低落 → 平静 → 高亢渐变。
-   中心圆形滑块表示当前情绪。
-   当前情绪文字位于仪表盘下方。

建议数据模型：

``` text
emotion_score: 0 ~ 100
emotion_level:
0~25   低落
26~50  平静
51~75  愉悦
76~100 高亢
```

交互：

-   用户可以左右拖动圆形滑块。
-   支持点击仪表盘位置改变分值。
-   分值变化时实时更新情绪名称。

#### 3. 快速记录卡片

默认 Placeholder：

> 写下你的心情...

支持：

-   点击进入文本输入。
-   多行输入。
-   最大长度建议 500～1000 字。
-   空内容时不允许直接保存或给出轻提示。

#### 4. 图片上传

-   最多 3 张。
-   第一格固定为添加按钮。
-   图片采用 1:1 或接近 1:1 的缩略图。
-   每张图片右上角提供删除按钮。
-   上传失败需要有明确错误反馈。

#### 5. 保存日记

主按钮：

``` text
背景：#6B4933
文字：#FFFFFF
圆角：16px
```

点击后：

``` text
保存成功
↓
进入 AI 回响生成流程
```

``` text
│ ……                      │

│          生活很美好，      │
│          你已经做得很好了 ♡│

┌────────────┐ ┌────────────┐
```

### AI 内容状态

必须设计三种状态：

#### Loading

``` text
✨ 今日回响
正在为你生成中...
```

可以使用：

-   呼吸动画
-   流动点
-   简单文字变化

不建议使用复杂 Lottie，避免产品过度科技化。

#### Success

展示：

-   AI 回响标题
-   情绪分析
-   暖心文案
-   分享按钮
-   重新生成按钮

#### Error

展示：

``` text
暂时没有生成成功
但你的这份记录已经好好保存了。

[重新生成]
```

注意：

**AI 失败不能影响日记保存。**

# 5.6 AI 回响说明

页面定位：

> 用简单、温暖的方式告诉用户 AI 回响是什么，以及它能做什么。

### 页面结构

顶部：

``` text
AI回响说明
```

视觉主体：

-   使用产品 IP 插画。
-   推荐使用「小芽 / 小植物」形象。
-   背景使用浅米黄色水彩纹理。

### 文案结构

``` text
AI 回响是什么？

AI 回响是基于你记录的内容，
结合情绪分析与大语言模型生成的
个性化情绪反馈与暖心文案。

它可以帮你：

✓ 分析你的情绪变化
✓ 发现生活中的闪光点
✓ 给出温暖、积极的鼓励
✓ 成为你生活中的陪伴者
```

底部：

``` text
记录，让生活更有意义 ♡
```

### 产品原则

需要明确：

-   AI 不替用户做心理诊断。
-   AI 输出属于生活陪伴与内容生成。
-   不使用「治疗」「诊断」等医疗化表达。
-   用户可以关闭 AI 分析。

# 11. AI 相关视觉规范


风格：

-   温柔

# 16. 最终 UI 风格总结

喃喃的核心视觉可以概括为：

> **「旧纸张 + 温暖棕色 + 低饱和情绪色 + 生活照片 + 轻量 AI」**

产品不追求强烈的科技感，而是通过：

``` text
暖米色背景
    +
柔和圆角卡片
    +
生活照片
    +
手账式排版
    +
低饱和情绪色
    +
AI 回响
```

形成「像一本会回应你的数字手账」的产品体验。

最终用户感受到的应该不是：

> 「我正在使用一个 AI 工具。」

而是：

> **「我在记录生活，而 AI 在认真听我说。」**

# 18. 与当前项目开发的关系

本 UI 稿作为「喃喃」MVP 前端实现的视觉与交互基准。

开发过程中：

1.  **优先保持信息架构不变。**
2.  可以根据微信小程序原生能力调整细节。
3.  不因为技术实现方便而破坏核心视觉风格。
4.  新增功能必须复用现有 Design System。
5.  如果 PRD 与 UI 发生冲突：
    -   先保证核心用户流程；
    -   再根据 MVP 范围调整；
    -   最终同步更新 PRD、TECH_SPEC 与 UI 设计稿。

推荐项目文档关系：

``` text
PRD.md
  ↓
定义「做什么」

TECH_SPEC.md
  ↓
定义「怎么实现」

UI设计稿.md
  ↓
定义「长什么样、怎么交互」

代码
  ↓
最终实现
```
